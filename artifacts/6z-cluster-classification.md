# Core 6Z article classification and writing map

Date: 2026-08-25

Scope: the 20 existing core South African Rand futures URLs listed below. Production URLs remain unchanged. Shared hubs, search index, sitemap, necessary related-reading links, the canonical green-and-black `currency-research-library.css`, validation/audit code, tests, and release artifacts are integration work rather than additional article assignments.

## Why 6Z is the current target

- The Currencies hub orders the fully rebuilt core libraries through 6S and places 6Z next.
- Rebuilds already exist for 6A, 6B, 6C, 6E, 6J, 6M, 6N, and 6S. The latest completed library is 6S, merged in PR 36.
- These 20 6Z pages are the next existing stale cluster. Their current copy relies on repeated structures and unsupported claims about fixed price zones, permanent indicators, predictable seasonality, guaranteed market behavior, and universal directional relationships.
- No other instrument cluster or isolated 6Z comparison page is in scope.

## Cluster editorial model

- One publication identity: Grizzly Parrot Trading / Kyle Parrott.
- One visual system: the existing shared green-and-black currency-library stylesheet and `fx-*` component namespace. No page-specific theme or alternate CSS.
- One evidence standard: primary sources for contract rules and official macro facts; mechanisms, hypotheses, empirical observations, and trading applications remain clearly distinguished.
- One contract-mechanics authority: `6z-tick-size-and-value.html`. It owns current CME unit, quotation, minimum increment, tick arithmetic, listed months, hours, termination/delivery, roll risk, and margin limitations.
- Unperformed empirical work is presented as a reproducible protocol, never as a result. Macro mechanisms are conditional rather than directional promises. Execution pages include explicit gates, invalidation, costs, and review.
- Page architecture follows the reader question. Openings, section sequences, evidence components, table shapes, pacing, and endings must vary.

## Cross-page ownership and anti-cannibalization

- `6z-tick-size-and-value.html` owns exchange mechanics and arithmetic. All other pages link to it and repeat only the minimum required for their calculation.
- `fundamental-drivers-of-6z.html` owns the daily multi-driver synthesis. SARB, rate-decision, USD, and structural-difference pages own their narrower mechanisms.
- `how-sarb-influences-6z.html` owns SARB institutional tools and communication. `sarb-rates-impact-6z.html` owns scheduled policy-decision interpretation.
- `6z-liquidity-map.html` owns descriptive market-quality mapping. `6z-algorithmic-behavior.html` owns actor-identification limits and automated-order hypotheses. `why-6z-slippage-hits-harder.html` owns realized execution-cost diagnosis.
- `6z-volatility-profile.html` owns state measurement. `6z-position-sizing.html` consumes that state in a risk-budget calculation, and `6z-trade-management-guide.html` owns the live position lifecycle.
- `best-times-to-trade-6z-futures.html` owns time-of-day market-quality testing. `6z-seasonal-patterns.html` owns calendar-horizon tests. `best-indicators-for-6z.html` owns candidate signal comparison.
- `why-6z-trades-differently.html` owns structural explanations. `6z-vs-6e-vs-6j-differences.html` owns instrument-selection comparison.
- `6z-trading-psychology.html` owns behavioral control design. `common-6z-trading-mistakes.html` owns failure-mode prevention and routes contract, sizing, and execution details to their canonical pages.

## Shared release gates

1. Every material factual claim has a descriptive primary-source link or explicit evidence label.
2. Current CME specifications and all calculations reconcile; broker day margin is never described as maximum loss.
3. Metadata, visible H1, Article schema, Breadcrumb schema, and any FAQ schema agree with visible content.
4. All pages use the single shared green-and-black stylesheet with no page-specific theme fork.
5. Headings, landmarks, navigation, tables, formulas, and scroll regions work at desktop and narrow widths.
6. Cluster validation, link checks, schema parsing, automated sameness audit, evidence review, editorial-distinctiveness review, visual QA, repository tests, and `git diff --check` all pass before release.
7. Hubs, search, sitemap, and necessary related-reading links are synchronized only after article content stabilizes.
